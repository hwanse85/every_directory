## 기능별 스크린샷 검증 추가

2026-10-23 같은 macOS 환경에서 전용 테스트 폴더를 만들고 프로덕션 서버의 UI를 조작했습니다. [54장 전체 갤러리](../output/playwright/feature-review/report.html)와 [검증 보고서](../output/playwright/feature-review/report.md)에 기능별 결과와 실행 로그를 정리했습니다.

- 일반 AND·구문·확장자·와일드카드·정규식·퍼지·초성 검색, 대소문자·이미지·전체 경로·여러 루트 필터를 확인했습니다. 작은 테스트 폴더의 6개 검색 화면에서 응답 표시값은 63.7~66.1ms였습니다.
- 탐색창 1~4개, 상하좌우 검색 배치, 분할 55%, 격자·좌우·위아래 배치, 독립 탭·즐겨찾기·목록/격자·뒤로/앞으로/상위·절대 경로 이동을 확인했습니다.
- 복사·이동·이름 변경·새 폴더·정규식과 순번을 조합한 일괄 이름 변경·ZIP 왕복·앱 휴지통 삭제/복원·다운로드 후 실제 디스크의 이름과 바이트를 대조했습니다. ZIP CRC와 SHA-256도 별도로 확인했습니다.
- 중복 덮어쓰기와 일괄 이름 충돌을 거부하고, 잘못된 정규식과 손상된 PDF를 안내하는지 확인했습니다.
- 텍스트·PNG·PDF·WAV·WebM 미리보기를 확인했습니다. PDF는 실제 캔버스의 문자 픽셀, 3쪽 문서의 페이지 이동·125% 확대, 390×844 화면에서도 확인했습니다. 오디오·동영상은 메타데이터와 음소거 재생을 확인했습니다.
- 외부 파일 추가 후 자동 인덱스 갱신, 브라우저 새로고침 후 연결 폴더·탭·즐겨찾기 복원을 확인했습니다. Finder와 TextEdit 화면도 실제로 촬영했습니다.

검증 중 PDF 플러그인 화면이 비어 있는 문제를 발견해 로컬 PDF.js Worker와 캔버스 렌더링으로 수정했습니다. 좁은 탐색창의 도구 버튼 잘림은 폭에 따른 아이콘 표시와 줄바꿈으로 수정하고, 4개 탐색창과 모바일에서 도구 모음의 가로 넘침이 없는지 재검증했습니다.

수정 후 `npm test` 21개와 `npm run build`가 통과했습니다. 정상 사용 흐름의 마지막 브라우저 콘솔은 오류·경고 0개입니다. 잘못된 입력을 의도적으로 실행한 HTTP 400과 손상된 PDF 경고는 별도 오류 처리 검증입니다. 최신 100,000개 합성 메타데이터 벤치마크의 가장 느린 검색 엔진 p95는 퍼지 75.29ms였습니다. 이 수치는 디스크 순회·HTTP·화면 반영을 제외하며 모든 데이터 규모에서 1초를 보장하는 결과는 아닙니다.
