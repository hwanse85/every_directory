# 빠른 검색 정확도·앱 밖으로 끌어 놓기·빠른 검색 밀도 — 0.12.1

## 빠른 검색에서 `yk5 xlsx`가 검색되지 않던 문제

- **원인**: 빠른 검색은 기본 설정이 **경로까지 검색**(설정 → 빠른 검색에서 경로도 검색)이다. 메인 검색은 기본이 파일명 검색이라 세 글자 색인 키로 후보를 바로 좁히지만, 경로 검색은 영문·숫자에 쓸 경로 색인이 없어 색인 전체를 훑었다. 빠른 검색의 응답 시간 제한(250ms)에 걸리면 그때까지 찾은 결과만 돌려주므로, 항목이 많은 PC에서는 `YK5 정산표.xlsx`처럼 색인 뒤쪽에 있는 파일을 찾기 전에 검색이 끝났다. 100만 항목 실험에서 81만 개까지만 훑고 0건이었다.
- 훑는 속도도 느렸다. 숨김 폴더 아래 항목을 거르려고 **모든 항목**마다 상위 폴더 수만큼 문자열을 새로 만들었다. Windows에서는 `AppData` 같은 숨김 폴더 아래 항목이 많아 비용이 컸다.
- **해결**
  - 빠른 검색은 먼저 파일명 색인으로 파일명 일치를 찾고, 남은 시간에 경로 일치를 더한다. 파일명 일치가 경로 일치보다 앞에 온다.
  - 숨김 폴더 확인은 검색어와 일치한 항목에만 하고, 문자열을 매번 새로 만들지 않는다.
  - 100만 항목에서 `yk5 xlsx` 빠른 검색이 251ms(부분 결과, 0건)에서 16ms(전체 확인, 1건)로 줄었다. 메인 검색의 경로 검색도 같이 빨라졌다.

## 검색·탐색 목록에서 앱 밖으로 끌어 놓기

- **원인**: 데스크톱 앱의 파일 끌기는 Windows 외부 드롭과 겹치지 않도록 앱 안에서만 도는 포인터 끌기였다. 운영체제 드래그가 시작되지 않아 브라우저·탐색기·Finder는 놓인 파일을 받지 못했다.
- **해결**: 끄는 중에 포인터가 창 밖으로 나가면 같은 항목으로 **운영체제 드래그**를 시작한다.
  - Windows: 셸 데이터 개체(`BHID_DataObject`)와 `SHDoDragDrop`. 탐색기와 같은 파일 형식과 끌기 이미지를 받는 앱에 제공한다.
  - macOS: 파일 URL과 Finder 아이콘으로 `NSDraggingSession`을 연다.
  - 받는 앱은 **복사**로 받는다(원본을 옮기지 않음). 브라우저 파일 업로드 칸, 메일 첨부, 탐색기·Finder 폴더, 바탕화면에 놓을 수 있다.
  - 창 안에서 탐색창 사이로 끄는 기존 동작(복사·이동 선택)은 그대로다.
  - 빠른 검색 결과도 끌어서 다른 앱에 놓을 수 있다. 빠른 검색 창 안에는 놓을 곳이 없으므로 끌기 시작부터 운영체제 드래그를 쓴다.
  - 마우스 단추를 이미 놓은 상태에서는 시작하지 않는다(놓친 단추 이벤트 때문에 커서 아래에 파일이 놓이는 일을 막는다).

## 빠른 검색 창 크기와 결과 밀도

- 기본 창 크기를 720×540에서 **860×680**으로 키웠다. 작은 화면에서는 작업 영역에 맞춰 줄인다. 클립보드 보기 확대 크기도 1120×820으로 키웠다.
- 결과 행 높이를 약 55px에서 **38px**로 줄였다. 이름 13px, 경로 11px, 아이콘 20px. 입력 줄과 구역 제목 여백도 줄였다.
- 한 번에 받는 결과를 12개에서 30개로 늘려 창에 10개 이상이 보이고 나머지는 목록을 내려 본다.

## 검증

- 단위 테스트: 깊은 폴더와 숨김 폴더가 섞인 20만 항목 색인에서 경로까지 빠른 검색(`yk5 xlsx`, `yk5`, `정산 xlsx`, `업무 yk5`)이 파일을 찾는지, 100만 항목 성능(무시 표시 테스트).
- 실제 앱 E2E(macOS·Windows 공용 `ux`, `quick`):
  - 빠른 검색 `yk5 xlsx`, 결과 행 높이와 한 화면 결과 수.
  - 창 안 끌기 표시와 창 밖으로 나갈 때 운영체제 드래그 전환.
  - 연결 폴더 밖 경로 거부, 단추를 누르지 않은 끌기 요청이 아무 곳에도 놓지 않음.
- 실제 마우스로 브라우저·탐색기·Finder에 놓는 동작은 자동화 환경에서 마우스 단추를 누를 수 없어 E2E로 확인하지 못했다. 사람이 직접 확인해야 한다.
