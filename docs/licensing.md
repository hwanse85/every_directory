# 앱 정보와 오픈소스·타사 고지

## 화면 구성

앱 정보와 타사 소프트웨어 고지는 서로 다른 목적이다.

- **앱 정보**: Every Directory의 버전, 확인 가능한 프로젝트 관리자와 저장소·문의 경로. 관리자 표시는 제공된 저장소의 소유 계정 `hwanse85`를 기준으로 하며 개인 실명이나 이메일을 추정하지 않는다.
- **구성요소 목록**: 포함하거나 빌드에 사용한 의존성의 이름·정확한 버전·SPDX 라이선스 표현식과 원본 소스 링크. 플랫폼별·빌드용 의존성도 포함된 목록이다.
- **THIRD_PARTY_NOTICES.txt**: 해당 구성요소의 라이선스 전문과 저작권·NOTICE 고지 모음. “Third party”는 이 앱 제작자 외의 타사 구성요소를 뜻한다. 설정에서는 “라이선스·저작권 고지 전문”으로 설명한다.

구성요소 이름과 라이선스 이름만 나열한 목록은 전문과 저작권 고지 보존을 대체하지 않는다. 기존 고지는 유지하고 앱에 내장해 오프라인에서도 읽을 수 있게 했다.

## 표시 의무와 앱 자체 라이선스

[MIT](https://opensource.org/license/mit)는 배포 시 원 저작권 고지와 허락 고지 보존을 요구한다. [Apache 2.0 제4조](https://www.apache.org/licenses/LICENSE-2.0)는 라이선스 사본, 해당되는 고지와 NOTICE, 수정 사항 표시 등을 규정한다. 이 원문들이 이 앱 제작자의 개인 실명이나 버전을 반드시 특정 설정 화면에 표시하도록 일반적으로 요구하는 것은 아니다. 제작자 정보·버전은 사용자 문의와 장애 분석을 위해 별도의 앱 정보로 제공한다. 다른 라이선스나 별도 계약·배포 경로의 조건은 따로 확인해야 한다.

[MPL 2.0 제3.2조](https://www.mozilla.org/media/MPL/2.0/index.txt)는 실행 형태를 배포할 때 해당 소스와 소스를 구할 수 있는 방법도 다룬다. 구성요소별 “원본 소스”는 잠금 파일의 정확한 버전의 crates.io 또는 npm 원본 아카이브로 연결한다. 이 저장소에서 수정한 제3자 소스를 별도로 배포한다면 수정본 제공 방법도 갱신해야 한다.

현재 저장소에는 앱 자체 이용 허락을 지정하는 LICENSE가 없다. **오픈소스 의존성을 사용하거나 저장소가 공개되어 있다는 사실만으로 Every Directory 전체에 MIT 등의 라이선스가 자동으로 적용되지는 않는다.** 앱 자체를 어떤 조건으로 배포할지는 저작권자가 정해야 하므로 임의의 라이선스를 부여하지 않았다.

## 이번 고지 보완과 자동 검사

의존성 목록의 npm 런타임 버전과 Cargo 잠금 버전은 일치했다. 하지만 Windows Cargo 의존성 7개는 기존 고지에 SPDX 선언만 있고 전문이 없었다. 원본 패키지의 VCS 커밋에 대응하는 상위 저장소 라이선스와 Mozilla의 MPL 원문으로 보완했다. 현재 설치된 npm 패키지의 누락 전문 4개도 추가했다. 기존 저작권·전문은 삭제하지 않았다.

```powershell
npm run licenses:check
npm run licenses:check -- --native
```

두 번째 명령은 Rust가 필요하고 Windows용 `cargo metadata --locked --offline --filter-platform x86_64-pc-windows-msvc` 결과까지 검사한다. 목록·버전·고지의 기계적 누락을 검사하며, 모든 배포 조건을 법적으로 확정하는 검사는 아니다. native 데스크톱에는 Node 서버와 sharp/libvips 등의 Node 네이티브 바이너리가 포함되지 않는다. Node 서버 또는 별도의 macOS/Linux 패키지를 재배포한다면 그 배포물의 실제 포함 항목과 조건을 다시 확인해야 한다.

고지를 갱신하려면 Cargo metadata JSON을 만든 뒤 `node scripts/supplement-windows-notices.mjs <metadata.json>`을 실행한다. 이 갱신 명령은 upstream 라이선스를 내려받으므로 네트워크를 사용한다. 일반 빌드와 고지 검사는 이미 저장된 전문을 이용한다.
