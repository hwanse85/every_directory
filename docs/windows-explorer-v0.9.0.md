# 탐색창·트리·미리보기·인덱스 제외 개선 — 0.9.0

## 요청별 반영 상태

| 요청 | 반영 |
|---|---|
| 트리 너비 유지 | 탐색창별 픽셀 너비 저장. 탭 전환·트리 숨김/표시·저장 설정 복원에 유지 |
| Windows 탐색기 기능 | 앱 안에 보기 8종·정렬·분류·속성 칼럼 선택 추가. 현재 폴더를 OS 기본 탐색기로 여는 버튼 제공. **Windows 탐색기를 완전히 내장한 상태는 아님** |

## 사용 방법

**트리 너비**: 트리 오른쪽 경계선을 드래그한다. 경계선에서 ←/→는 10px, Shift+←/→는 40px, Home·더블클릭은 165px 기본값이다. Esc로 드래그를 취소한다. 80~600px로 저장하며 작은 창에서는 파일 목록을 남기기 위해 표시 폭을 제한한다. 창을 다시 넓히면 저장 폭을 사용한다. 탭별 펼침 상태와 창별 너비를 별도로 저장한다.

**보기·정렬·분류**: 탐색창의 필터 아래 설정 줄을 사용한다. 아주 큰/큰/보통/작은 아이콘, 간단히, 자세히, 타일, 내용 보기를 제공한다. 정렬 기준과 방향은 아이콘 보기에서도 조절할 수 있다. 분류는 이름·유형·확장자·크기·날짜 등으로 구분하며 ‘없음’으로 해제한다. 그룹 헤더에는 항목 수를 표시하고 파일 선택 대상에서 제외한다. 그룹 접기/펼치기는 아직 제공하지 않는다.

**속성 칼럼**: ‘표시 항목’ 또는 헤더 우클릭에서 선택한다. 이름·위치·유형·확장자·크기·수정일·연결 폴더·만든 날짜·액세스한 날짜·특성·전체 경로의 11개를 제공한다. 이름은 항상 표시한다. 칼럼 경계 드래그·자동 맞춤도 유지한다. 보기·정렬·분류·칼럼은 창별로 저장하며 다른 창에 영향을 주지 않는다. 검색 결과에서 파일을 표시할 때도 사용자가 선택한 보기 종류를 강제로 바꾸지 않는다.

만든 날짜는 파일 시스템의 생성 시각이다. 지원하지 않는 값은 ‘—’로 표시한다. 접근 시각은 OS의 기록 정책에 따라 갱신되며 파일을 읽었다고 항상 즉시 바뀌지는 않는다. 탐색창은 현재 파일 시스템 메타데이터를 읽고, 검색 표는 인덱스 스냅샷을 사용한다. 접근 시각만 바뀌었다고 인덱스 버전을 올리지는 않아 탐색 중 검색 페이지가 초기화되는 일을 방지한다. 검색 인덱스의 접근 시각을 새로 읽으려면 다시 인덱싱한다. 기존 인덱스에 없는 새 속성은 재인덱싱 후 채워진다.

**미리보기**: 파일 선택 후 Space. 텍스트는 14px/1.65 줄 간격으로 표시한다. PDF 도구 모음과 페이지 스크롤 영역은 분리한다. 긴 파일명은 말줄임한다. Esc 또는 닫기 버튼으로 복귀한다. 창 크기 확대는 읽기 한도나 지원 형식을 바꾸지 않는다.

**제외 폴더**: 사이드바 ‘인덱스 관리’ → 연결 폴더의 ‘제외 폴더’ → 하위 폴더 선택 또는 상대 경로를 줄마다 입력 → ‘저장하고 다시 인덱싱’. 예: `백업`, `자료/임시 파일`. 줄을 지우고 저장하면 다시 포함한다. 존재하지 않는 경로도 나중에 생길 폴더의 규칙으로 저장할 수 있다. 연결 폴더당 128개까지 지원한다.

제외는 그 연결 폴더에만 적용한다. 같은 하위 폴더를 별도 루트로 연결했다면 별도 루트의 규칙도 설정해야 한다. `자료`는 `자료함`을 제외하지 않는다. Windows에서는 대소문자를 구분하지 않는다. 절대 경로·상위 경로·빈 경로는 거부한다. `.git`, `node_modules`, 앱 내부 작업/휴지통 폴더, 심볼릭 링크에 대한 기존 기본 제외 정책은 유지한다. 파일을 삭제하거나 이동하지 않는다. 저장에 실패하면 기존 인덱스를 유지한다.

탐색창은 인덱스 제외 폴더도 직접 열 수 있다. 인덱스에서 제거한 파일이 탐색창에서도 사라지는 일을 방지하기 위해 파일 탐색과 검색용 인덱스를 분리했다. 경로 검증·심볼릭 링크 거부·연결 폴더 범위 제한은 유지한다.

## Windows 기본 탐색기를 그대로 사용하는 방안

[Microsoft의 File Explorer 안내](https://support.microsoft.com/en-gb/windows/experience/fileexplorer/file-explorer-in-windows?nochrome=true)를 기준으로 주요 보기·정렬·분류·속성 선택을 보강했다. **현재 앱은 Windows Shell 전체와 동등하지 않다.** 다음 기능은 ‘기본 탐색기에서 열기’로 OS 창에서 사용할 수 있으며 앱 내부에 전부 이식한 것은 아니다.

- 타사 Shell 확장 우클릭, 모든 Windows 속성·연결 형식 설명, 태그·평가·소유자·문서/미디어 전용 칼럼
- Windows 휴지통과 일반 실행 취소, 가상 폴더·라이브러리·네트워크 인증 UI
- Windows의 모든 썸네일·미리보기 처리기, 압축 내부 탐색, OS 버전별 추가 기능

기본 탐색기 버튼은 **현재 폴더의 별도 OS 창을 연다.** 이후 OS 창의 이동·보기 설정이 앱 탭에 다시 동기화되지는 않는다. 앱의 ‘아이콘’ 보기는 파일 유형 아이콘이며 Windows의 전체 썸네일 처리기를 사용하지 않는다. 기본 유형은 확장자 기반이며 실제 Shell의 모든 속성 처리기를 호출하지 않는다.

완전 내장은 공식 [IExplorerBrowser](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-iexplorerbrowser)로 검토할 수 있다. Microsoft가 Shell 뷰와 탐색 기록을 제공하지만, WebView2 위에 메뉴 하나를 붙이는 변경은 아니다. 아래 조건을 충족하는 선택형 Windows 모드를 후속 단계로 권장한다.

| 방식 | 장점 | 고려 사항 | 현재 상태 |
|---|---|---|---|
| 현재 React 탐색창 | 초성 필터·검색 결과 연결·다중 창·교차 플랫폼 일관성 | Shell 기능을 직접 구현해야 함 | 기본 모드 |
| 별도 OS 탐색기 | OS의 기능·속성·확장 메뉴를 즉시 사용 | 앱 탭과 별도 상태 | 버튼 제공 |
| IExplorerBrowser 내장 모드 | 앱 창 안의 기본 Shell 뷰 활용 가능 | STA/COM 수명, HWND·WebView2 겹침, DPI, 탭 이벤트·선택 동기화, 팝업/모달·드래그·단축키 처리 필요 | 설계·검증 대상으로 남음 |

내장 모드 완료 기준: 창 4개·탭 전환·100/150/200% DPI·여러 모니터·메뉴와 미리보기 모달·복사/이동 취소·네트워크 재연결·탐색 상태 동기화·종료 후 COM/창 자원 회수. 현재 별도 OS 창 버튼을 ‘완전 내장’으로 표현하지 않는다.

## 검증 기록과 한계

실제 Windows Tauri/WebView2 15개 묶음의 245개 검증, TypeScript/웹 서비스 65개, Rust 62개가 통과했다. 전체 E2E 244개 통과 후 폴더 유형 표시 검증을 추가한 탐색창 묶음을 다시 실행해 245개로 집계했다. Rust는 기본 59개와 대용량 분석·실제 C↔D 볼륨 이동·100만 항목 초성 검색의 별도 3개다. 선택 실행인 시작·20만 검색·전송 벤치마크 3개는 이번에 재실행하지 않았다.

새 검증에는 트리 드래그·탭 전환·저장값 복원, 보기 8종, 날짜 칼럼, 분류 선택, 미리보기 크기, 제외 설정·파일 탐색 유지가 포함된다. 인덱스 갱신 중 검색 다중 선택 보존도 추가했다. 배포 확인은 배포 폴더의 `verification.json`에 기록한다.

이번 실행 장비는 Windows 11이다. Windows 10 물리 장비·모든 IME·Shell 확장·SMB·DPI/다중 모니터의 전체 조합을 검증했다는 의미는 아니다. 트리 폭 UI 복원은 WebView 재로드, 제외 규칙의 디스크 복원은 새 Rust 엔진 인스턴스로 각각 확인한다. 배포 설정은 localStorage에 저장하며 검증 설정은 사용자 설정과 분리한 저장소를 사용한다.

## English

Version 0.9.0 persists tree width per pane, expands Space previews, adds eight views plus sorting/grouping and configurable columns, and supports per-root indexing exclusions without removing folders from browsing. File-system creation/access timestamps and basic attributes are available. Search selection survives unrelated index updates; access-only changes do not invalidate result pages.

This is not a fully embedded Windows Explorer. The native Explorer button opens the current folder in a separate OS window. Shell-specific features, arbitrary property handlers, native undo/recycle bin, virtual folders and full thumbnail integration remain distinct from the React pane. The proposed next step is an optional IExplorerBrowser mode with explicit COM, focus, DPI and tab-synchronization tests.
