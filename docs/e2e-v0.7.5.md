# 0.7.5 초성 검색과 E2E 검증

2026-10-24, Windows x64, `codex/project-work`. 테스트는 사용자 폴더·설정과 분리한 임시 데이터 및 실제 WebView2에서 실행했다. 앱 버전은 프런트엔드·npm·Cargo·Tauri 모두 0.7.5로 맞췄다.

## 재현과 수정

1. **초성 시간 제한**: 이전 Rust 엔진은 초성 모드에서 이름·경로를 전체 순회했다. 250ms(빠른 검색)·650ms(메인 검색) 한도 전에 뒤쪽 파일을 만나지 못하면 부분 결과 또는 0건으로 표시될 수 있었다. 초성 경로의 두/세 글자 역색인을 추가했다. AND의 필수 후보 중 가장 작은 집합, OR의 후보 합집합을 검사하며 제외 조건은 후보를 잘못 제거하지 않는다. 숫자·영문만 있는 캐시 경로는 별도 초성 포스팅을 만들지 않고 인덱스 위치는 32비트로 저장해 메모리 증가를 줄였다.
2. **자모와 IME**: 변경 전 실제 WebView E2E에서 독립 자모·반각 자모 입력, 탐색창 초성 필터, IME 조합 중 값 보존이 실패했다. 완성 음절의 NFC는 보존하면서 자모와 겹받침을 통일하고, IME 조합 확정 전에는 앱이 입력값을 바꾸지 않게 했다. `ㅂㄱㅅ`, `ㅆㄹㅁㅇㄷ`, 혼합 음절과 초성, NFD·반각 붙여넣기를 검증했다.
3. **폴더·명령 필터**: 현재 폴더와 명령 검색에도 초성·혼합·와일드카드 필터를 연결했다. 명령 창의 IME 확정 Enter는 명령을 실행하지 않는다.
4. **파일 작업 요청**: 목록 갱신 중 메뉴 요청을 처리 완료로 기록하고 버릴 수 있었다. 같은 위치에서 목록이 준비될 때까지 보류하고, 위치가 바뀌면 이전 요청을 실행하지 않게 했다.
5. **격자 탐색**: 처음 300개 제한에서 추가 항목으로 접근할 수 있도록 “다음 파일 더 보기”를 추가했다. 310개 이상 실제 파일, Ctrl 다중 선택, 목록 전환 후 선택 유지를 검증했다.
6. **앱 정보·타사 고지**: 버전·프로젝트 관리자·문의 경로와 타사 고지를 분리했다. 의존성별 원본 소스 링크, 고지 로딩 재시도와 버전·고지 누락 검사를 추가했다. 자세한 내용은 [라이선스 안내](licensing.md)를 참고한다.

## 엔진·대량 검색과 검증 경계

- `npm test`: 39개 통과. Node 서버의 검색·실제 파일·ZIP·감시·이미지·OCR·HTTP 경계를 포함한다.
- `npm run test:rust`: 검색·파일 작업·클립보드 경계·분석·인덱스 복원·Windows 긴 경로 등을 검사한다. 대량 벤치마크는 명시적으로 실행한다.
- `npm run test:rust -- --test windows --test search_scale -- --include-ignored --nocapture`: 100만 항목 끝에 있는 보고서와 된소리 파일을 메인/빠른 검색에서 부분 결과 없이 찾는지 검사한다. 결과 완결성과 실제 검사 후보 수를 함께 확인한다. AND/OR/제외·경로·와일드카드는 전체 항목의 직접 매칭 결과와도 대조한다.
- 인덱스 구성 시간은 검색 응답 시간과 다르다. 합성 데이터의 측정치를 모든 PC·검색어에 대한 보장으로 해석하지 않는다. 지나치게 넓은 한 글자·정규식 검색 등에는 시간 제한과 부분 결과 표시가 남아 있다.

자동 검사에서 제외한 범위는 기본 앱 및 외부 브라우저의 실제 실행, OS 폴더 선택·저장 대화상자의 물리 입력, 로그인·재부팅 후 자동 시작, 실제 SMB 서버의 인증·재연결, 다중 모니터/DPI, macOS 실기기이다. 저장·열기 엔진 경계는 별도의 Rust/HTTP 테스트로 검사하지만 이 범위를 GUI E2E 통과로 계산하지 않는다. 네이티브 데스크톱에서 제공하지 않는 OCR은 Node 서버 테스트로 구분한다.

일반 배포 빌드에는 E2E 스크립트와 검증 IPC가 포함되지 않는다. 수정 확인 시 설정의 앱 버전이 **0.7.5**인지 확인한다.
