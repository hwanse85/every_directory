# 색인 없이 모든 경로 탐색, 편의 아이콘 편집, UU 인코딩·디코딩, 탐색창 단추 초점선

## 1. 상단 '탐색창' 단추의 초점선

**문제**
- 단추는 격자 아이콘, 글자, 화살표로 이루어진 `<label>`이고, 그 안에 실제 선택 상자(`<select>`)가 있습니다.
- 누르면 초점선이 안쪽 선택 상자에만 그려졌습니다. 그래서 아이콘이 테두리 밖에 남았습니다.

**수정**
- 선택 상자 자체의 초점선은 없앴습니다.
- 대신 단추 전체(`:focus-within`)에 초점선을 그리고, 눌렀을 때의 배경도 단추 전체에 칠합니다.

## 2. 편의 아이콘 추가·삭제·순서 변경

**배치**
- 기본 아이콘(검색 · 도구 · 레이아웃 · 탐색창)은 고정입니다. 그 뒤에 편의 아이콘 묶음(`QuickToolbar`)을 두었습니다.
- 기본 구성: 새 탭, 새 폴더, 새로 고침, 클립보드 이력, UU 인코딩, UU 디코딩.
- 더 고를 수 있는 항목: 홈 폴더 열기, 숨김 파일 전환, 다른 탐색창으로 복사, 두 탐색창 폴더 비교, 용량 분석, 중복 파일, 일괄 이름 변경, 터미널, 앱 휴지통, 빠른 검색 창, 명령 찾기.

**편집**
- 연필 단추를 누르거나 아이콘 위에서 우클릭하면 편집 팝업이 열립니다.
- 체크 상자로 보이기·숨기기, ↑↓로 순서 바꾸기, '기본 아이콘으로 되돌리기'를 할 수 있습니다.
- 구성은 `toolbarItems` 설정에 저장되고, 모르는 항목은 불러올 때 버립니다.

**좁은 창**
- 상단 줄의 남는 폭을 재서 들어가는 만큼만 아이콘을 보여 줍니다.
- 나머지는 연필 단추에 `+n`으로 표시하고, 팝업 맨 위에서 바로 실행합니다. 900px 창에서도 상단 줄이 넘치지 않습니다.

## 3. 색인 없이 모든 경로 탐색(이 PC)

**문제**
- 탐색 목록은 원래 디스크를 직접 읽습니다.
- 그런데 경로 확인(`resolve`)이 연결 폴더와 색인 항목만 받았습니다. 그래서 D 드라이브만 연결하면 C 드라이브는 열 수 없었습니다.

**설계**
- **탐색 전용 위치(`browse: true`, id는 `pc:`로 시작):**
  - 홈 폴더(`pc:home`)
  - Windows: 모든 드라이브 문자(`GetLogicalDrives`)
  - macOS: `/`(이 Mac)와 `/Volumes`의 외장·네트워크 볼륨(시동 디스크를 가리키는 링크는 뺌)
- **id로 바로 만들기:** `volumes::place(id)`가 id에서 위치를 바로 만듭니다. 경로를 열 때마다 모든 드라이브를 훑지 않아 네트워크 드라이브가 느려도 영향이 없습니다.
- **경로 확인(`resolve_place`):**
  - 색인 확인 없이 디스크에 있는지만 봅니다.
  - `..`, 절대 경로, 앱 내부 폴더는 막습니다.
  - `/var`·`/tmp` 같은 링크 경로도 입력한 표기 그대로 따라갑니다. 그래야 목록 항목의 경로와 주소가 어긋나지 않습니다.
- **함께 고친 곳:**
  - 목록(`list`): 탐색 위치에서는 `.git`·`node_modules`도 보여 줍니다.
  - 주소 확인(`directory_location`)
  - 즐겨찾기·최근 항목(`quick_access::entry`)
  - 보호(`protect`): 드라이브·홈 폴더와 그 상위 항목은 지우거나 옮길 수 없습니다.
- **삭제:** 탐색 위치에서 지우면 앱 휴지통 폴더를 만들지 않고 운영체제 휴지통으로 보냅니다.
  - macOS: `NSFileManager trashItemAtURL`
  - Windows: `SHFileOperationW` + `FOF_ALLOWUNDO`
- **검색:** 탐색 위치는 색인·감시·검색 대상이 아닙니다.

**화면**
- 사이드바에 **이 PC** 목록을 추가했고, 폴더 트리에도 연결 폴더 아래에 함께 보입니다.
- 주소 칸은 가장 긴 경로가 맞는 위치를 고릅니다. 연결 폴더 안이면 그 연결 폴더, 아니면 이 PC 위치입니다.
- 탭 기록·작업 공간을 되살릴 때 `pc:` 위치도 그대로 유지합니다.
- 드라이브를 꽂거나 빼면 창으로 돌아올 때 목록을 다시 읽습니다.

## 4. UU 인코딩·디코딩(백그라운드, 상태 막대 진행률)

**형식(sfk uuencode와 같음)**
- `begin 644 이름` 다음에 한 줄 45바이트를 61자로 적고, `` ` `` 와 `end`로 끝냅니다.
- 0은 공백 대신 `` ` ``로 써서, 줄 끝 공백이 잘린 파일도 되살립니다.

**실행**
- 우클릭 → 파일 도구 → UU 인코딩·디코딩, 또는 상단 편의 아이콘으로 시작합니다.
- 만들 파일 이름을 묻습니다. 기본값은 인코딩이면 `이름.uue`(폴더는 `폴더.zip.uue`), 디코딩이면 `.uue`를 뗀 이름입니다.

**백그라운드 작업(`codec.rs`)**
- 별도 스레드에서 실행하고, 0.1초마다 `ed-job` 이벤트로 진행률을 보냅니다.
- 결과는 같은 폴더의 임시 파일(`.ed-work-…`)에 쓰고, 다 되면 새 이름으로 옮깁니다(같은 이름이 있으면 멈춤).
- 취소하거나 실패하면 임시 파일이 지워져, 반쯤 만든 파일이 남지 않습니다.
- 폴더는 기존 ZIP 압축 코드로 묶은 뒤 인코딩합니다.
- 디코딩은 begin 앞뒤의 메일 머리글 같은 다른 줄과 CRLF 줄바꿈을 받아들입니다. end가 없거나 begin이 없으면 이유를 알려 줍니다.

**상태 막대(`JobBar`)**
- 창 맨 아래에 작업마다 진행 막대·퍼센트·크기·취소 단추를 보여 줍니다.
- 완료·취소는 6초 뒤 사라지고, 오류는 닫을 때까지 남습니다.
- 끝나면 탐색창 목록을 다시 읽습니다.

## 검증

- **Rust 단위 테스트:**
  - 표준 예시 `Cat` ↔ `#0V%T`
  - 0~45바이트 모든 길이와 모든 바이트 값 왕복
  - 파일 전체 왕복: 빈 파일~100KB, CRLF 줄바꿈, 앞뒤 다른 줄
  - 끊긴 파일·일반 파일 거부, 취소
- **E2E(macOS 실제 앱):**
  - **explorer:**
    - 이 PC 목록과 사이드바
    - 연결 폴더 밖 경로를 주소로 열기
    - 이 PC 위치는 검색에 나오지 않음
    - 목록 안 이름 바꾸기
    - 연결 폴더로 복사
    - 운영체제 휴지통으로 삭제
    - 홈 폴더 자체 삭제 차단
  - **actions:**
    - 이미지 인코딩 → 디코딩 후 SHA-256 일치
    - 폴더 → ZIP → 인코딩 → 디코딩 → 압축 해제 후 원래 파일 확인
    - uuencode가 아닌 파일은 오류 표시와 함께 파일을 만들지 않음
  - **layout:**
    - 탐색창 단추 초점선이 단추 전체를 감쌈
    - 편의 아이콘 위치와 기본 구성
    - 추가·삭제·순서 변경과 재실행 후 유지
    - 클립보드·홈 아이콘 실행
    - 900px 창의 `+n` 넘침 처리
- **Windows:** Windows 대상 컴파일만 확인했고(`cargo xwin check`, smoke-test 포함), Windows 휴지통 동작은 실제 PC에서 확인하지 않았습니다.
- **주의:** E2E는 이 PC 위치 삭제를 검사하면서 실제로 macOS 휴지통에 `바깥 이름변경.txt`를 하나 넣습니다.
