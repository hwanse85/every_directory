# 탐색창 정렬·보기·분류 수정 (0.13.0 이후)

탐색창의 **정렬**·**보기** 단추와 **분류(그룹)** 기능을 Windows 실기(WebView2)에서 실제 마우스 입력으로 점검하고 고친 기록이다.

## 정렬

- **정렬 기준 목록이 잘렸다.** 기준은 11개인데 목록 상자를 8줄로 자르고 스크롤 막대를 숨겨(`overflow: hidden`) 액세스한 날짜·특성·전체 경로를 마우스로 고를 수 없었다. 이제 모든 기준을 한 번에 보여 준다(창이 낮으면 메뉴 패널 전체가 스크롤된다).
- **이름 순서가 Windows 탐색기·검색 결과와 달랐다.** 탐색창은 `Intl.Collator("ko")`로 비교해 한글 이름을 영문보다 앞에 두었다. 언어 미지정(`"und"`)은 한국어 Windows에서 `ko-KR`로 풀려 같은 문제가 남으므로 `"en"`을 명시했다. 순서는 기호 → 숫자(자연 순서, 2 < 10) → 영문 → 한글이다.
- 크기·날짜 등 값이 같으면 이름순으로 둔다. 전체 선택·선택 반전·목록 내보내기도 화면 순서를 따른다.

## 보기·메뉴

- WebView2가 창 크기 변화 없이 보내는 `resize`에는 정렬·보기·도구·칼럼·탭 메뉴를 닫지 않는다. 창 크기가 실제로 바뀔 때만 닫는다(`src/viewportResize.ts`).
  - 배율 100% 실기에서는 재현되지 않았다. 125%·150% 같은 분수 배율에서 "눌러도 반응 없음"처럼 보이는 경우를 막는 방어 수정이다.

## 분류(그룹)

| 기준 | 이전 | 이후 |
|---|---|---|
| 유형 | 폴더 묶음이 파일 묶음 뒤 | 폴더 묶음을 맨 앞 |
| 확장자 | 폴더가 "미지정" 묶음으로 맨 뒤 | "폴더" 묶음으로 맨 앞, 확장자 없는 파일은 "확장자 없음" |
| 특성 | 일반 파일이 "미지정" | "일반" |
| 이름 | 숫자마다 묶음(1, 2, 3…) | 0–9 · 영문 대문자 · 한글 초성(겹자음은 기본 자음, ㄲ → ㄱ) · # |
| 전체 경로 | 항목마다 묶음 하나 | 분류 기준에서 제외(저장된 값은 분류 없음으로 처리) |

- 분류 기준과 정렬 기준이 같으면 묶음 순서도 정렬 방향을 따른다(예: 크기 내림차순이면 큰 묶음부터). 기준이 다르면 날짜는 최근 것부터, 나머지는 오름차순이다. 폴더 묶음은 맨 앞, "알 수 없음"은 맨 뒤에 고정한다.

## 키보드

- Home·End·PageUp·PageDown·첫 글자 찾기로 먼 항목에 가면 선택만 옮겨지고 키보드 초점은 이전 행에 남거나 문서로 빠지는 경우가 있었다. 가상 목록이 다음 `scroll` 이벤트에서야 대상 행을 그렸기 때문이다. 스크롤 상태를 바로 맞추고 대상 행이 그려질 때까지 짧게 다시 시도해 초점을 옮긴다. 분류 머리글이 끼면 더 자주 생기던 문제다.

## 검증

- 단위 테스트 81개 통과(분류 규칙·정렬 순서 테스트 추가).
- Windows 11 WebView2 E2E 20개 묶음·501개 검사 통과. 추가 검사: 정렬 기준 목록 전체 표시, 이름 정렬 순서, 크기 변화 없는 `resize`에도 메뉴 유지, 유형·확장자 분류의 폴더 묶음, 0–9·초성 묶음, 분류 목록의 End·Home 초점.
- 실제 마우스 입력(`SendInput`)으로 정렬 기준·방향·분류 드롭다운·보기 종류 변경을 확인했다.
- 확인하지 못한 것: 분수 배율 PC에서의 `resize` 동작, macOS 실기.
