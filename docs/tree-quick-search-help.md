# 폴더 트리 들여쓰기, 빠른 검색 클립보드 키워드, 검색 방식 사용법, 내장 도움말

## 1. 폴더 트리 들여쓰기

**문제**
- 단계마다 12px씩 같은 간격으로 들여썼습니다.
- 기본 트리 폭(165px)에서는 7단계쯤부터 폴더 이름이 ‘첨…’처럼 잘려 보이지 않았습니다.

**바꾼 점**
- **들여쓰기 간격(`treeIndent`):** 1~2단계는 12px, 3~5단계는 8px, 그보다 깊은 단계는 4px로 점점 줄입니다. 들여쓰기 전체는 트리 폭에서 96px를 뺀 값을 넘지 않아, 아이콘과 이름이 들어갈 자리가 항상 남습니다.
- **단계 안내선:** 상위 단계마다 펼침 단추 가운데에 가는 세로선을 그립니다. 간격이 좁아져도 어느 단계인지 알아볼 수 있습니다. 밝은 화면과 어두운 화면에 맞는 색을 따로 씁니다.
- **여백:** 트리 안쪽 여백과 이름 사이 간격을 줄였습니다.
- **툴팁:** 마우스를 올리면 폴더의 전체 경로가 보입니다.

**결과**
- 8단계(`문서/2026/분기/설계 검토 자료/기계 계통/배관 해석/첨부`)에서도 기본 폭 안에 이름이 다 보입니다.
- 웹 미리보기에서 바꾸기 전과 후를 찍어 비교했습니다.

## 2. 빠른 검색의 클립보드 키워드

- 설정한 키워드 말고도 `clip`, `클립`, `클립보드`를 입력하면 결과 맨 위에 **클립보드 보기**가 나옵니다.
  - 대소문자와 앞뒤 공백은 따지지 않습니다.
  - 한글은 분리형(NFD)으로 들어와도 같은 말로 봅니다.
  - 판단은 `isClipboardKeyword`가 합니다.
- 설정의 키워드 설명도 이에 맞게 고쳤습니다.

**클립보드 창 검사(quick 스위트에 추가)**
- **키워드:** `clip`·`클립`·`클립보드`로 각각 클립보드 보기가 맨 위에 뜨는지 확인합니다.
- **이미지 탭:**
  - 이미지 이력만 보이고, 그림이 실제로 그려지는지(`naturalWidth > 0`) 확인합니다.
  - ‘텍스트로 복사’가 꺼져 있는지 확인합니다.
  - ‘클립보드로 복사’를 누른 뒤 시스템 클립보드에 이미지가 들어가는지 확인합니다.
- **파일 탭:**
  - 파일 이력만 보이고, 원본 경로가 미리보기에 나오는지 확인합니다.
  - ‘클립보드로 복사’를 누르면 시스템 클립보드에 파일로 들어가 붙여넣을 수 있는지 확인합니다.
  - ‘텍스트로 복사’를 누르면 경로가 글자로 복사되는지 확인합니다.
- **확인 방법:** 화면 단추로 복사한 뒤 시스템 클립보드를 다시 기록합니다. 가장 최근 이력의 종류와 경로로 결과를 판단합니다.

## 3. 검색 방식 점검과 사용법 툴팁

**엔진 직접 검사(search 스위트에 21개 항목 추가)**
- **일반:**
  - 공백은 AND, `|`는 OR, `!`는 제외로 동작하는지 확인합니다.
  - `ext:`, `"구문"`도 확인합니다.
- **와일드카드:**
  - `*`는 여러 글자, `?`는 정확히 한 글자인지 확인합니다. `IMG_????.jpg`가 `IMG_12.jpg`는 찾지 않아야 합니다.
  - 이름 전체와 비교하는지 확인합니다. `보고서`만으로는 ‘업무 보고서.txt’를 찾지 않아야 합니다.
  - 대소문자를 무시하는 경우와 구분하는 경우를 모두 확인합니다.
- **정규식:**
  - 시작·끝 고정, 묶음과 OR, 날짜 형식을 확인합니다.
  - 대소문자를 무시하는 경우와 구분하는 경우를 모두 확인합니다.
  - 전후방 탐색을 쓰면 지원하지 않는다는 안내가 나오는지 확인합니다.
- **퍼지:**
  - 3~5글자는 오타 1자를 허용하고 2자는 허용하지 않는지 확인합니다.
  - 6글자 이상은 오타 2자까지 허용하는지 확인합니다.
  - 한글 오타도 찾는지 확인합니다.
  - 2글자 이하는 정확히 포함할 때만 찾는지 확인합니다.
- **화면에서도:** 정규식·와일드카드·퍼지 결과가 결과 목록에 나오는지 확인합니다.

모든 항목이 기대대로 동작해, 고친 검색 결함은 없습니다.

**사용법 툴팁**
- 검색 방식 옆에 **?** 단추를 두었습니다. 마우스를 올리거나 키보드 초점을 두면 현재 방식의 한 줄 설명과 예시 3~4개가 뜹니다.
- 단추를 누르면 도움말의 해당 방식 설명으로 바로 이동합니다.
- 검색 방식 선택 상자에도 같은 요약을 `title`로 달았습니다.

## 4. 내장 HTML 도움말

**내장 방식**
- 도움말은 `src/help/help.html` 한 파일입니다.
- Vite의 `?raw` 가져오기로 빌드할 때 프로그램 안에 문자열로 들어갑니다. 배포 파일 옆에 따로 둘 파일이 없습니다.

**화면(`HelpCenter`)**
- 왼쪽에 목차, 오른쪽에 문서를 둡니다.
- 목차는 스크롤 위치를 따라 현재 절을 표시합니다.
- **도움말에서 찾기:** 검색어가 든 절만 남기고, Enter를 누르면 첫 절로 갑니다.
- 문서 안의 링크는 앱 주소를 바꾸지 않고 해당 절로 이동합니다.
- 운영체제마다 수정 키를 다르게 보여 줍니다. Windows는 Ctrl, macOS는 ⌘입니다.
- 한쪽 운영체제에만 있는 기능(Windows 새로 만들기, F5 동작 등)은 그 운영체제에서만 보입니다.
- 밝은 화면·어두운 화면을 모두 지원하고, 창이 좁으면 목차가 위로 갑니다.

**내용(15개 절)**
1. 시작하기
2. 화면 구성
3. 검색하기
4. 검색 방식(방식별 표와 상세 설명)
5. 검색 연산자·조건
6. 검색 결과 다루기
7. 탐색창
8. 폴더 트리
9. 파일 작업
10. 이름 바꾸기·새로 만들기
11. 빠른 검색 창
12. 클립보드 이력
13. 설정
14. 단축키 모음
15. 문제 해결

**열기:** F1, 사이드바의 도움말, 검색 방식의 **?** 단추(해당 절로 바로 이동).

## 검증

- **단위 테스트:** `isClipboardKeyword`, `treeIndent`.
- **E2E:**
  - **search:** 검색 방식 21개 항목, 툴팁, 도움말 절 이동
  - **quick:** 클립보드 키워드, 이미지·파일 탭과 복사
  - **tree:** 8단계 폴더 이름 표시와 단계 안내선
  - **audit:** F1 도움말
