# Every Directory

Everything 방식의 파일 검색과 Q-Dir 방식의 다중 탐색창을 결합한 **로컬 서버 + 브라우저 앱**입니다. 서버가 실행되는 PC의 실제 폴더를 인덱싱하고 탐색합니다. 원본 Everything·Q-Dir 프로그램이나 Everything SDK에는 의존하지 않습니다.

## 실행

Node.js 22.13 이상과 npm이 필요합니다. 최초 한 번 설치·빌드합니다.

```sh
npm install
npm run build
npm start
```

간편 실행은 macOS에서 `start-macos.command`, Windows에서 `start-windows.cmd`를 사용합니다. 의존성이 없으면 설치한 뒤 빌드하고 서버를 실행합니다. Node.js는 먼저 설치해야 합니다.

브라우저에서 **http://127.0.0.1:5173/** 을 엽니다. 서버 프로세스는 실행 상태로 유지합니다. 개발 중에는 `npm run dev:web` 한 번으로 같은 주소에서 서버와 Vite 화면을 함께 실행합니다. 프런트엔드만 실행하면 파일 API가 동작하지 않습니다.

다른 포트와 인덱스 위치를 지정할 수도 있습니다.

```sh
# macOS / Linux
PORT=5180 EVERY_DIRECTORY_DATA=/absolute/path/to/index-data npm start
```

```powershell
# Windows PowerShell
$env:PORT = "5180"
$env:EVERY_DIRECTORY_DATA = "C:\EveryDirectoryData"
npm start
```

## 사용

1. **폴더 연결**을 누릅니다. 로컬 폴더를 클릭해 이동하거나 절대 경로를 입력하고 **이동**을 누릅니다.
2. **이 폴더 연결**을 누르면 해당 폴더와 하위 폴더를 인덱싱합니다. 여러 루트를 각각 연결할 수 있습니다.
3. 검색 방식을 선택하고 파일명을 검색합니다. 결과를 **한 번 클릭하면 활성 탐색창에 파일 위치를 열고 해당 파일을 선택**합니다. **더블 클릭하거나 Enter를 누르면 기본 앱으로 실행**합니다. 폴더는 활성 탐색창에서 엽니다.
4. 탐색창에서 파일을 더블 클릭하면 미리보기를 엽니다. 다운로드도 가능합니다.
5. 각 탐색창의 `+`로 독립 탭을 추가합니다. **레이아웃**에서 위치·배치·비율을, **탐색창 개수**에서 1~4개를 설정합니다. 기본값은 검색 왼쪽, 탐색 오른쪽, 탐색창 2개입니다.
6. 체크박스나 Ctrl/Cmd·Shift 클릭으로 항목을 선택하고 탐색창 도구 모음에서 파일 작업을 실행합니다. 복사·잘라내기 후 다른 탐색창에서 붙여넣을 수 있습니다.

처음에는 **첫 번째 탐색창이 활성 상태**입니다. 탐색창 내부를 클릭하거나 초점을 이동하면 활성 창이 바뀝니다. 각 창 오른쪽 위의 번호·활성 버튼과 보라색 테두리로 표시하며, `F6`으로도 순서대로 전환합니다. 새로고침하면 첫 번째 창부터 시작합니다.

헤더의 **빠른 명령** 버튼 또는 `Ctrl/⌘ + Shift + P`로 도구·명령을 검색하고 방향키·Enter로 실행할 수 있습니다. 파일 작업 명령은 활성 탐색창에서 선택한 항목에 적용합니다.

연결 전에는 **샘플 공간**을 표시합니다. 샘플은 실제 파일이 아닙니다.

## 파일 작업과 추가 도구

| 기능                   | 사용법                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| 새 폴더·이름 변경      | 탐색창 도구 모음. 이름 변경 단축키 F2                                                     |
| 복사·잘라내기·붙여넣기 | Ctrl/Cmd+C·X·V. 연결한 폴더 사이의 파일·폴더를 처리                                       |
| 다중 선택              | 체크박스, Ctrl/Cmd 클릭, Shift 클릭, 활성 탐색창에서 Ctrl/Cmd+A                           |
| 삭제·복원              | Delete/Backspace → 확인 후 앱 휴지통으로 이동. `추가 파일 도구 → 앱 휴지통 · 복원`        |
| ZIP 압축·해제          | 선택 항목을 ZIP으로 압축. ZIP 하나를 선택해 `추가 파일 도구 → ZIP 압축 풀기`              |
| 일괄 이름 변경         | `추가 파일 도구`. 문자열·정규식 치환, 접두사·접미사, 순번, 확장자 유지와 변경 전 미리보기 |
| 빠른 미리보기          | 파일 하나를 선택하고 Space. 텍스트·이미지·PDF·미디어                                      |
| 이미지 크기 변경       | PNG·JPEG·WebP 1~50개 선택 → `추가 파일 도구`. 비율 유지·자르기·늘이기, 형식 변경, 사본 저장 |
| 이미지 텍스트 추출     | 이미지 하나 선택 → `추가 파일 도구 → 이미지 텍스트 추출 · OCR`. 한국어·영어, 수정·복사·TXT 다운로드 |
| 빠른 명령 검색         | `Ctrl/⌘ + Shift + P`. 명령 이름·키워드 검색, 탐색창 전환, 파일 도구 실행                  |
| 속성·SHA-256           | `추가 파일 도구`. 폴더의 총 파일 수·크기, 개별 파일 해시                                  |
| OS 연동                | `추가 파일 도구 → Finder / 탐색기에서 보기`, `기본 앱으로 열기`                           |

PowerToys의 PowerRename·Peek 작업 흐름을 참고한 자체 기능입니다. PowerToys 설치가 필요하지 않으며 전체 PowerToys 기능을 포함하지 않습니다.

- 같은 이름이 있으면 덮어쓰지 않고 중단합니다. 이동할 폴더의 하위 폴더나 같은 위치에는 붙여넣을 수 없습니다. 연결 루트 자체를 이름 변경·이동·삭제하려면 먼저 연결을 해제합니다.
- 파일 클립보드는 앱 안의 탐색창들이 공유합니다. Finder·Windows 탐색기의 파일 클립보드와 연동하지 않습니다. 경로 문자열 복사는 OS 클립보드를 사용합니다.
- 삭제는 **OS 휴지통이 아닌 연결 루트의 `.every-directory-trash` 폴더**로 이동합니다. 앱의 복원 도구에서 원래 위치로 복원합니다. 연결을 해제해도 휴지통은 남고 같은 폴더를 다시 연결하면 복원할 수 있습니다. 원래 상위 폴더가 있어야 하며 같은 이름의 항목이 있으면 복원을 중단합니다. 휴지통 자동 비우기는 없습니다.
- 다른 드라이브로 이동하면 대상 복사를 완료한 뒤 원본은 앱 휴지통으로 옮깁니다. 작업은 서버에서 순서대로 수행하며 완료 후 연결 루트를 다시 인덱싱합니다. 여러 항목 처리 중 오류가 나면 앞선 항목은 완료되어 있을 수 있습니다.
- ZIP 해제는 새 폴더로만 수행하며 10,000개 항목·총 2GB 한도입니다. 암호화·심볼릭 링크·경로 탈출·Windows 예약 이름은 거부합니다. ZIP 이외의 압축 형식은 지원하지 않습니다.
- 일괄 이름 변경은 적용 전 전체 이름 충돌을 검사합니다. 일반 실행 취소와 비교·동기화는 아직 없습니다.
- 이미지 크기 변경은 새 결과 폴더에 사본을 저장하며 원본을 유지합니다. 파일당 50MB·4천만 픽셀, 출력 가로·세로 8192px·4천만 픽셀 이하이며 정지 이미지만 지원합니다. PNG·JPEG·WebP로 저장할 수 있고 같은 이름의 결과 폴더는 덮어쓰지 않습니다. 기본값은 비율 유지와 확대 금지입니다.
- OCR은 Tesseract.js와 함께 설치한 한국어·영어 모델을 로컬 Worker에서 실행합니다. 실행 중 외부 모델 다운로드나 이미지 업로드가 없습니다. 한 번에 이미지 하나를 처리하며 텍스트 인식 단계는 90초로 제한합니다. 인식 결과와 신뢰도를 표시하고 내용을 수정·복사·TXT 다운로드할 수 있습니다. 사진·서체·해상도에 따라 오류가 있어 결과 검토가 필요합니다.

## macOS와 Windows

같은 Node.js 서버와 브라우저 UI를 사용하도록 구현했습니다. 폴더 선택기는 macOS 경로와 Windows 드라이브 경로를 처리하고, 생성·이름 변경에서 Windows 예약 이름과 금지 문자를 검사합니다. macOS에는 `open`, Windows에는 `explorer.exe`를 사용하는 OS 연동 경로가 있습니다.

**macOS에서 실제 파일 작업과 Chromium UI를 검증했습니다. Windows 실기기 검증은 아직 수행하지 않았습니다.** 저장소에 등록해 실행할 수 있는 macOS·Windows·Linux / Node.js 22 CI 구성을 추가했으며, CI 실행 결과를 확인한 상태는 아닙니다. 현재 배포 형태는 로컬 서버이며 exe 설치 파일은 제공하지 않습니다.

## 검색 방식

| 방식       | 입력 예                                       | 동작                                                               |
| ---------- | --------------------------------------------- | ------------------------------------------------------------------ |
| 일반       | `프로젝트 보고서`                             | 두 단어를 모두 포함하는 파일명                                     |
| 구문       | `"업무 계획"`                                 | 공백까지 연속으로 포함                                             |
| 확장자     | `보고서 ext:pdf,docx`                         | 지정 확장자 필터와 검색 조합                                       |
| 와일드카드 | `*보고서*.pdf`, `IMG_????.jpg`                | `*` 여러 글자, `?` 한 글자. 전체 파일명에 적용                     |
| 정규식     | `^report_\d+\.pdf$`, `보고서.*\.(pdf\|docx)$` | RE2 문법의 정규식 부분 일치. `^`·`$`로 경계 지정                   |
| 퍼지       | `raedme`                                      | `README.md` 같은 오타·인접 문자 바뀜을 허용하고 정확한 일치를 우선 |
| 한글 초성  | `ㅂㄱㅅ`, `ㅍㄹㅈㅌ ㅂㄱㅅ`                   | 보고서, 프로젝트 보고서 등 초성 검색                               |

- 일반·와일드카드·퍼지·초성에서 공백은 AND이고 `ext:` 필터를 함께 사용할 수 있습니다.
- 정규식 모드에서는 **전체 입력을 패턴**으로 해석합니다. 확장자는 패턴 또는 파일 유형 필터로 제한합니다. 전후방 탐색·역참조는 지원하지 않으며 잘못된 패턴은 화면에 오류를 표시합니다.
- 기본은 대소문자 구분 없음입니다. **대소문자** 체크로 변경합니다. 초성 모드에서는 영문 대소문자를 구분하지 않습니다.
- 퍼지는 단어 단위로 3~5자에 편집 1회, 6~64자에 2회를 허용합니다. 1~2자 및 65자 이상 입력은 정확한 부분 일치만 적용합니다.
- 파일 유형·루트 폴더 필터를 조합할 수 있습니다. 설정의 **전체 경로**는 연결 폴더 안의 상대 경로까지 검색합니다.
- 검색어 최대 512자, 화면 결과 최대 1,000개입니다. 전체 일치 수는 별도로 표시합니다. 탐색창 격자 보기는 처음 300개를 표시합니다.
- 검색 엔진 작업이 약 650ms를 넘으면 확인한 결과를 반환하고 **부분 결과**라고 표시합니다. 이때 결과 수는 전체 개수가 아닙니다. 검색 폴더나 조건을 좁혀 주세요.

## 인덱스와 파일

- 파일명·상대 경로·종류·크기·수정일을 인덱싱합니다. **파일 내용 검색은 구현하지 않았습니다.**
- 연결 정보와 완료 인덱스는 기본적으로 사용자 홈의 `.every-directory/index.json`에 저장합니다. 브라우저 저장소를 지워도 서버 인덱스는 유지됩니다. 화면 설정·탭·즐겨찾기는 브라우저에 저장합니다.
- 파일 변경 이벤트를 750ms 동안 묶어 해당 루트를 다시 인덱싱합니다. 완료 후 화면이 다음 상태 확인(약 1초 간격)에 갱신됩니다. 대용량 폴더는 순회 시간이 추가됩니다. 재시작 시 저장 인덱스를 복원하고 연결 폴더를 다시 확인합니다.
- 재인덱싱에 실패하면 마지막 완료 인덱스를 유지합니다. 변경 감시 오류는 **인덱스 관리**에서 확인합니다. **새로고침**으로 수동 재인덱싱할 수 있습니다.
- `.git`, `node_modules`, 앱 인덱스 저장 폴더·앱 휴지통·내부 작업 폴더와 심볼릭 링크는 인덱싱에서 제외합니다. 읽을 수 없는 항목도 건너뛰고 제외 수를 표시합니다. 폴더 복사·압축은 내부 휴지통·작업 폴더를 제외한 실제 내용을 처리하며, 하위 심볼릭 링크가 있으면 중단합니다.
- 파일 읽기·작업은 연결 폴더 내부의 인덱싱된 경로로 제한합니다. 연결 해제는 저장 인덱스와 감시를 제거하고 원본 파일과 앱 휴지통을 유지합니다.
- 텍스트 미리보기는 처음 256KB, 이미지·PDF·미디어는 스트리밍합니다. 다운로드는 전체 파일입니다.
- PDF는 로컬 PDF.js로 한 페이지씩 표시하며 이전/다음 쪽과 확대를 지원합니다. 주석·양식 편집은 지원하지 않습니다.
- 서버는 `127.0.0.1`에만 바인딩합니다. 로컬 세션·동일 오리진 확인을 사용하며 외부 서비스로 파일이나 인덱스를 업로드하지 않습니다.

## 검증과 성능

```sh
npm test
npm run build
npm run benchmark
```

2026-10-23 Apple M3 Max / 64GB / Node.js 26 환경에서 24개 자동 테스트와 실제 Chromium 브라우저 검사를 수행했습니다. 이미지 크기·형식 변경과 원본 보존, 실패 시 부분 결과 정리, 한국어·영어 OCR을 실제 파일로 검사합니다. v0.2에서 측정한 합성 메타데이터 100,000개의 30회 반복 검색에서 다섯 방식 모두 부분 결과 없이 완료했고, 가장 느린 퍼지 검색의 엔진 p95는 약 **77ms**였습니다. v0.3~0.4는 검색 엔진을 변경하지 않았습니다.
