# 사용자 설정 저장 단추 고정과 닫기 전 확인 — 0.12.4

## 문제

- 설정 창의 사용자 설정(숨김 파일 표시, 검색 결과 선택 시 탐색창 따라가기, 글자 크기, 클립보드 설정 등)은 **‘사용자 설정 저장’을 눌러야** 저장된다.
- 이 단추가 사용자 설정 목록 맨 아래(클립보드 설정 밑)에 있어 잘 보이지 않았다.
- 저장하지 않고 X·Esc·바깥 클릭으로 닫으면 바꾼 값을 **알림 없이 버렸다**. 설치형·포터블 모두 같았다. 포터블의 저장 위치(`portable-data`) 문제는 아니었다.

## 해결

- ‘사용자 설정 기본값 복원’과 ‘사용자 설정 저장’ 단추를 **설정 창 아래에 고정**했다. 창을 어디까지 스크롤해도 보인다.
- 저장하지 않은 변경이 있으면 고정 영역에 “저장하지 않은 변경이 있습니다.”를 강조해 표시한다.
- 저장하지 않은 변경이 있는 채로 X·Esc·바깥 클릭으로 닫으려 하면 창을 닫지 않고 묻는다.
  - **저장하고 닫기**: 저장한 뒤 닫는다.
  - **저장하지 않고 닫기**: 바꾼 값을 버리고 닫는다.
  - **계속 편집**: 창을 그대로 둔다.
- 기본 검색 방식·자동 시작·트레이·계속 실행·단축키·화면 테마·목록 밀도는 이전처럼 고르는 즉시 저장한다.

## 검증

- 실제 앱 E2E(`portable`, macOS 실행 지원 추가): 실행 파일 옆 `portable.flag` 배치에서 실제 설정 창을 눌러 확인했다.
  - 저장 단추가 창을 열었을 때와 끝까지 내렸을 때 모두 아래에 보이는지.
  - 저장하지 않고 닫기·Esc가 저장 여부를 묻는지, ‘저장하지 않고 닫기’는 저장하지 않는지.
  - ‘저장하고 닫기’·‘사용자 설정 저장’으로 저장한 값과 기본 검색 방식이 재실행 후 설정 창에 그대로 보이는지.
  - 설정 파일이 실행 파일 옆 `portable-data`에 저장되는지.
- 검증하지 못한 것
  - Windows 실기에서 포터블·설치형 저장은 직접 확인하지 못했다. Windows CI의 포터블 스위트가 같은 검사를 돈다.
  - 화면 테마·목록 밀도는 검증 빌드가 화면 저장소를 분리하므로 재실행 유지를 E2E로 확인하지 못했다.
