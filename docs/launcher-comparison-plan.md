# Alfred · Spotlight 등과의 비교, 차별점과 개선 계획

2026-11-15 · 기준 소스 0.12.6(9dae693 이후)

## 1. 요약

- **Every Directory는 '런처'가 아니라 '파일 찾기 + 파일 다루기' 도구다.** Alfred·Spotlight·Raycast는 앱 실행·계산·웹 검색·자동화까지 하는 만능 입력창이다. 이 프로젝트는 Everything 같은 즉시 파일명 검색과 Q-Dir·Windows 탐색기 같은 다중 탐색창을 한 화면에 묶었다.
- **강점은 한국어 업무 환경이다.**
  - 한글 초성·혼합 검색, Everything식 검색 연산자, 다중 탐색창의 파일 작업을 Mac과 Windows에서 같은 화면으로 제공한다.
  - 네트워크 드라이브 색인과 오프라인 동작을 지원한다.
- **약점은 셋이다.** 파일 내용 검색이 없고, 결과 순위가 사용 이력을 거의 배우지 않으며, 확장 방법이 없다. 빠른 검색 창은 런처 수준의 동작(앱 실행·계산·사용자 동작)을 하지 않는다.
- **권장 방향:** 런처 전체를 따라가지 않는다. 대신 아래 넷을 차례로 보강한다. 앱 실행은 마지막에 선택 기능으로만 검토한다.
  1. 한국어 검색 품질(이번 수정과 한/영 자판 보정)
  2. 학습형 순위
  3. 파일 동작
  4. 선택형 내용 검색

## 2. 비교 대상과 기준

| 제품 | 성격 | 플랫폼 | 비고 |
|---|---|---|---|
| **Every Directory** | 파일명 검색 + 다중 탐색창 + 파일 작업 | macOS · Windows | Tauri 2 + Rust, 로컬 색인 |
| **Spotlight** | 운영체제 내장 검색 | macOS | 전체 디스크 메타데이터·본문 색인. macOS 26부터 작업 실행·클립보드 기록·빠른 키가 추가됨 |
| **Alfred 5** | 키보드 런처 | macOS | 파일 검색은 Spotlight 색인 사용. Powerpack(유료)에서 워크플로·클립보드·스니펫·파일 탐색 |
| **Raycast** | 확장형 런처 | macOS(Windows판 공개 중) | 확장 스토어, 창 관리, 클립보드, AI 기능 |
| **Everything** | 파일명 즉시 검색 | Windows | NTFS MFT·USN 저널 사용, 본문 검색은 선택 기능 |
| **PowerToys Command Palette** | 런처 | Windows | 앱·파일·명령, 확장 가능 |

- 경쟁 제품의 내용은 2026년 6월까지 공개된 정보와 일반적인 사용 경험에 근거한다.
- 최신 버전에서 달라졌을 수 있으므로, 계획을 확정하기 전에 각 제품에서 직접 확인해야 한다(특히 Spotlight·Raycast의 한국어 처리와 Windows판 범위).

## 4. 차별점 — 지키고 키울 것

1. **한국어 검색 품질**
   - 초성, 초성·음절 혼합, 겹자음 분리를 지원한다.
   - 반각·조합형 자모(NFD)를 통일하고, 띄어쓰기와 구분 기호를 무시한다.
   - 이번에 입력 중인 음절(도깨비불) 처리도 더했다.
   - 비교 대상 중 이 수준으로 한국어를 다루는 제품이 없다. 국내 업무 문서(`보고서_v2`, `[초안]`, `(2026.03)` 같은 이름)에 맞춰져 있다.
2. **검색과 탐색·작업의 한 화면 통합**
   - 결과에서 바로 탐색창으로 열고, 두 창 사이에서 복사·이동하고, 목록 안에서 이름을 바꾸고, 압축·비교·중복 찾기까지 이어진다.
   - Spotlight·Alfred는 찾은 뒤 Finder로 넘긴다.
3. **Everything식 정밀 검색을 Mac에서도 쓴다.** 정규식, 와일드카드, `size:`·`dm:` 범위, OR·NOT·그룹을 macOS에서도 같은 문법으로 쓴다.
4. **업무망 친화**
   - SMB·WebDAV·클라우드 폴더를 색인하고, 오프라인으로 동작한다.
   - 개인 경로를 빌드에서 지우고 개인정보 검사를 한다.
   - 포터블 실행을 지원한다. 사내 PC처럼 설치·권한이 제한된 환경에 맞다.
5. **안전한 파일 작업**
   - 덮어쓰지 않고, 앱 휴지통으로 복원할 수 있다. 연결 폴더 밖은 OS 휴지통으로 보낸다.
   - 작업을 직렬로 처리하고, 하위 폴더로의 이동을 막는다.

## 5. 개선이 필요한 점

| # | 부족한 점 | 사용자에게 미치는 영향 | 비교 대상 |
|---|---|---|---|
| G1 | **한/영 자판을 잘못 두고 친 검색어**(`qhrhtj` = 보고서)를 알아듣지 못함 | 한국어 사용자의 가장 흔한 실수인데 결과가 0건 | 네이버·구글은 보정, 런처는 대부분 없음 → **차별화 기회** |
| G2 | 결과 순위가 **고른 이력을 배우지 않음** | 같은 검색어로 매번 같은 파일을 찾아 내려가야 함 | Alfred·Spotlight·Raycast 모두 학습 |

| G5 | 메타데이터 조건이 크기·수정일뿐 | 만든 날짜·종류 묶음·Finder 태그·작성자로 좁힐 수 없음 | Spotlight `kind:`·`date:`·태그 |
| G6 | 빠른 검색의 **동작이 고정** | ‘다른 앱으로 열기’, ‘압축해서 메일로’, ‘경로를 특정 형식으로 복사’ 같은 반복 작업을 못 줄임 | Alfred 유니버설 액션·워크플로, Raycast 확장 |
| G7 | 색인 범위를 **직접 연결**해야 하고 첫 색인이 느림 | 처음 쓰는 사람은 “왜 안 찾아지지?”를 겪음. Windows 대용량 볼륨은 시간이 걸림 | Spotlight 자동, Everything은 MFT로 수 초 |
| G8 | **서명·공증·자동 업데이트** 없음 | Windows SmartScreen·macOS Gatekeeper 경고가 뜨고, 새 버전을 직접 받아야 함 | 모두 서명·자동 업데이트 |

| G10 | 결과 강조·미리보기가 빠른 검색 창에서 제한적 | 비슷한 이름이 많을 때 고르기 어려움 | Spotlight 미리보기 패널, Alfred Quick Look |

## 6. 개선 계획

원칙은 셋이다.

- 한국어 검색과 파일 작업이라는 강점을 먼저 깊게 만든다.
- 런처 기능은 파일 작업과 맞닿는 것만 고른다.
- 단계마다 측정 가능한 완료 기준과 Mac·Windows E2E를 둔다.

### 0단계 — 완료(이번 변경): 초성 + 일반 검색 보강

**확인한 문제**
- 숫자·영문·특수문자를 섞은 검색어 48개는 원래 잘 찾았다.
- 다만 다음 두 경우에는 결과가 0건이었다.
  1. 파일 이름의 구분 기호를 빼고 입력한 경우: `ㅂㄱㅅ2026` → ‘보고서-2026-03.pdf’, `ㅇㅁㅂㄱㅅ` → ‘업무_보고서.txt’
  2. 한글을 치는 도중 마지막 음절에 받침이 붙은 순간: ‘보곳’, ‘횡’, ‘회읠’

**고친 내용**
- 한글이 든 검색어는 글자 사이의 공백·구분 기호를 건너뛴다. 입력한 기호는 그대로 비교한다.
- 마지막 음절의 받침을 다음 글자의 첫소리로도 본다. 겹받침은 뒤 자음만 넘긴다(‘값’ → ‘갑’ + ㅅ).
- 같은 규칙을 데스크톱 엔진(Rust)과 탐색창 필터·결과 강조·웹 버전(TypeScript)에 적용했다.

**검증**
- 혼합 검색어 68개를 확인했다. 파일명·전체 경로 검색, 일반·빠른 검색 모두에서 찾았다.
- 엉뚱한 파일을 찾지 않는지 4개 사례로 확인했다.
- 기존 Rust 테스트 전체, 단위 테스트 76개, macOS E2E(search·quick·explorer·desktop)가 통과했다.

### 1단계 — 한국어 검색 완성과 학습형 순위 (약 2~3주)

| 작업 | 내용 | 완료 기준 |
|---|---|---|
| **한/영 자판 보정** (G1) | 결과가 0건이거나 아주 적고 검색어가 두벌식 영문 배열로 한글이 되는 경우, 바꾼 한글로 다시 찾는다. ‘○○(으)로 찾은 결과’로 알려 주고, 원래 검색어로 되돌릴 수 있게 한다. 반대 방향(`ㅁㅔㅡ` → `apm`)도 같다. | `qhrhtj` → 보고서, `ghldmlfhr` → 회의록. 영문 파일 `report`가 보정 때문에 가려지지 않음. 50만 항목에서 추가 지연 50ms 이내 |
| **학습형 순위** (G2) | (검색어 앞부분, 고른 파일)의 쌍을 기록한다. 사용 빈도와 최근성을 섞어 같은 품질 등급 안에서 앞으로 올린다. 기록은 로컬에만 두고, 설정에서 지우거나 끈다. | 같은 검색어로 두 번 고른 파일이 세 번째에 1위. 기록 1만 건에서 검색 지연 증가 10ms 이내 |
| **영문 약어 검색** (G3) | CamelCase·`_`·`-`·공백으로 나눈 단어의 첫 글자를 ‘영문 초성’처럼 색인한다. 초성 + 일반 방식에서 함께 찾는다. | `mbr` → MyBigReport.pdf, `ubs` → user_build_script.sh. 기존 결과 순서는 유지(약어 일치는 아래에 둠) |
| 검색 품질 회귀 표 | 이번 `initials_mixed` 시험을 실제 업무 파일 이름 300개 표본으로 넓힌다. | CI에서 Mac·Windows 모두 통과 |

### 2단계 — 파일 동작과 메타데이터 (약 3~4주)

| 작업 | 내용 | 완료 기준 |
|---|---|---|
| **빠른 검색 동작 확장** (G6) | 작업 메뉴(Tab)에 다음을 더한다. ‘다른 앱으로 열기’(OS 연결 프로그램 목록), ‘압축해서 보내기’, ‘경로 형식 복사’(UNC·`file://`·따옴표), ‘탐색창 두 곳에 나란히 열기’, ‘이름 바꾸기’. | 키보드만으로 3단계 이내 실행. 각 동작 E2E |
| **사용자 동작** (G6, 확장의 축소판) | 설정에서 ‘이름 + 실행할 명령 + 인자 틀(`{path}`, `{dir}`, `{name}`)’을 등록하면 작업 메뉴에 나온다. 셸을 거치지 않고 인자 배열로 실행한다. 처음 실행할 때 확인을 받는다. | 명령 삽입 시험(따옴표·`;`·`&&`가 든 이름)에서 의도한 프로그램만 실행 |
| **메타데이터 조건** (G5) | `dc:`(만든 날짜), `da:`(접근일), `kind:문서/이미지/…`, macOS Finder 태그(`tag:`), Windows 읽기 전용·숨김 속성 조건을 추가한다. | 각 조건의 범위·경계값 단위 테스트, 도움말 연산자 표 갱신 |
| 빠른 검색 미리보기 (G10) | 선택한 항목의 미리보기 패널(이미지·PDF 첫 쪽·텍스트 앞부분)을 연다. Space로 켜고 끈다. | 10MB 이하 파일 300ms 이내 표시 |

### 3단계 — 색인 확장과 본문 검색 (약 4~6주, 선택 기능)

| 작업 | 내용 | 완료 기준 |
|---|---|---|
| **첫 실행 색인 제안** (G7) | 첫 실행 때 홈의 문서·데스크톱·다운로드를 기본 제안하고, 진행률·예상 시간을 보여 준다. | 새 사용자가 폴더 연결 없이 첫 검색에 성공 |
| **Windows NTFS 빠른 색인** (G7) | 관리자 권한이 있으면 MFT·USN 저널로 첫 색인과 증분 갱신을 한다. 권한이 없으면 지금 방식으로 자동 전환한다. | 100만 파일 볼륨 첫 색인 1분 이내. 저널이 끊기면 전체 재색인 |
| **본문 검색** (G4) | 설정에서 켜는 별도 내용 색인이다. txt·md·코드·PDF 텍스트·docx·xlsx·pptx·hwpx를 대상으로 하고, 파일당 크기·총 용량 한도를 둔다. `content:` 연산자로 찾는다. 첫 단계에서 OCR은 넣지 않는다. | 1만 문서 색인 10분 이내, 내용 검색 1초 이내. 색인 용량은 원본의 10% 이하. 끄면 색인 삭제 |
| macOS Spotlight 연동(대안) | 본문 검색을 직접 만들기 전에 `mdfind` 결과를 ‘본문 일치’ 그룹으로 합치는 시험판을 만든다. | 연결 폴더 범위로만 제한. 결과 출처 표시 |

### 4단계 — 배포 품질과 런처 기능 검토 (병행·선택)

| 작업 | 내용 | 비고 |
|---|---|---|
| **서명·공증·자동 업데이트** (G8) | Windows 코드 서명, macOS Developer ID 서명·공증, Tauri updater(서명된 업데이트 파일)를 적용한다. | 인증서 비용·보관 정책 결정 필요 |
| 앱 실행·계산 (G9) | 빠른 검색에서 `/Applications`와 시작 메뉴의 앱을 결과 맨 위 그룹으로 보여 주고, 간단한 계산식 결과를 표시한다. **기본은 꺼 둔다.** | 런처와 겹치므로 사용자 요구를 확인한 뒤 결정 |

## 8. 측정

- **검색 성공률:** 빠른 검색에서 결과를 고른 비율, 결과 0건 비율. 로컬 통계만 쓰고 외부로 보내지 않는다.
- **찾는 데 걸린 시간:** 단축키를 누른 때부터 열기까지 걸린 시간의 중앙값.
- **순위 품질:** 고른 결과의 평균 순위. 1단계 뒤 1.5위 이내를 목표로 한다.
- **성능:** 20만·50만 항목 벤치마크(`engine benchmark`)에서 검색 650ms 한도 안의 완료율 99% 이상을 유지한다.
