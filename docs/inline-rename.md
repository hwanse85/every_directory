# 탐색창 안에서 바로 이름 바꾸기

이름을 묻던 작은 창을 없앴습니다. 이름 바꾸기와 새로 만들기는 이제 Windows 탐색기처럼 목록 행 안에서 바로 처리합니다.

## 바뀐 동작

| 작업 | 이전 | 이후 |
|---|---|---|
| 이름 바꾸기 (F2, 우클릭 메뉴, 도구 막대) | 이름 입력 창이 뜸 | 행의 이름 자리가 입력칸으로 바뀜. 파일은 확장자 앞까지만 선택됨 |
| 새 폴더 (Ctrl/⌘ Shift N, 도구 막대, 메뉴) | 이름 입력 창 | `새 폴더`를 바로 만들고 그 행에서 이름 입력. 같은 이름이 있으면 `새 폴더 (2)` |
| 새 텍스트 파일 | 이름 입력 창 | `새 파일.txt`를 바로 만들고 이름 입력 |
| ZIP 압축 | 이름 입력 창 | `원본 이름.zip`으로 바로 압축하고 이름 입력 |
| ZIP 압축 풀기 | 폴더 이름 입력 창 | ZIP 이름의 폴더에 바로 풀고 이름 입력 |
| Windows 새로 만들기(셸 메뉴) | 만든 뒤 F2를 따로 눌러야 함 | 하나를 만들면 바로 이름 입력 |
| 탭 이름 변경 | 이름 입력 창 | 탭 머리글 안에서 입력. 탭을 두 번 눌러도 시작 |
| 검색 결과의 이름 바꾸기 | 이름 입력 창 | 검색 결과 행 안에서 입력. 바꾼 뒤 새 이름 결과를 다시 선택 |

입력칸 조작:
- **Enter·Tab**: 적용.
- **Esc**: 취소.
- **다른 곳 클릭**: 적용.
- 다른 앱으로 잠시 옮겨 가도 편집은 유지됩니다. 다른 곳에서 이름을 복사해 와 붙여넣을 수 있습니다.

입력칸이 바로 막는 경우와 남겨 두는 경우:
- 쓸 수 없는 문자나 예약 이름(예: `CON.txt`)은 서버에 보내기 전에 막습니다.
- 같은 이름이 이미 있는 등 서버가 거절하면 입력칸이 그대로 남습니다. 빨간 테두리와 바로 아래 안내로 이유를 보여 줍니다.
- 이름을 바꾸지 않고 적용하면 아무 작업도 하지 않습니다.
- 적용하면 새 이름의 항목을 선택하고, 키보드로 끝냈으면 그 행에 초점을 둡니다.

다음 작업은 그대로 창을 씁니다:
- **일괄 이름 변경:** 미리보기 표가 필요합니다.
- **휴지통으로 이동:** 실수로 지우지 않도록 확인합니다.
- **속성, 이미지 변환:** 입력할 항목이 많습니다.
- **검색 결과의 압축:** 만든 항목이 검색 결과에 나오지 않습니다.

## 점검한 결함: 이름을 붙여넣었는데 파일이 붙여넣어짐

**결과:** 실제로 생기는 현상이었고, 원인은 두 가지였습니다.

1. **F2 창이 열려도 초점이 이름 칸에 가지 않았습니다.**
   - 원인: `autoFocus`가 동작할 때는 대화상자가 아직 열리기 전입니다. 그래서 `showModal()`이 첫 단추인 **닫기**로 초점을 옮겼습니다.
   - 결과: 이 상태에서 Ctrl+A·Ctrl+C를 누르면 이름이 아니라 대화상자 글자 전체가 복사됐습니다. 브라우저에서 실제 키 입력으로 확인했습니다.
2. **목록을 다시 읽는 동안 누른 F2가 아무 표시 없이 무시됐습니다.**
   - 이름을 바꾸거나 폴더 내용이 바뀌면 목록을 다시 읽고, 그동안 파일 작업 단추와 단축키가 잠깁니다.
   - 이때 누른 F2는 버려지고 창이 열리지 않았습니다. 목록이 다 읽힌 뒤 이어서 누른 Ctrl+V는 이름 칸이 아니라 파일 목록으로 갔습니다. 그래서 앞서 복사해 둔 파일이 `(1)` 사본으로 붙여넣어졌습니다.
   - 목록 응답을 700ms 늦춰 재현했습니다.

**수정:**
- 이름 입력칸은 목록 행 안에 바로 만들어지고 초점과 선택을 그 자리에서 잡습니다. 이름 칸에서 누른 Ctrl+V는 언제나 글자 붙여넣기입니다.
- F2와 메뉴의 이름 바꾸기는 목록을 다시 읽는 중에도 바로 시작합니다(이름 바꾸기는 새 목록이 필요 없습니다).
- 다른 파일 작업 단축키는 지금처럼 목록이 준비된 뒤에 받습니다.

## 구현

- `FileTable`의 `RenameField`
  - 행 안의 입력칸입니다. 확장자 앞 선택, Enter·Tab·Esc 처리, 다른 곳 클릭 시 적용, 오류 표시를 맡습니다.
  - 입력칸의 키·포인터 이벤트가 행의 열기·선택·끌기 동작으로 번지지 않게 막습니다.
  - 편집할 때마다 새 `token`으로 다시 만들어, 같은 항목을 이어서 고쳐도 이전 상태가 남지 않습니다.
- `FileActions`
  - `onRename`을 받은 탐색창은 이름 바꾸기와 새 폴더·새 파일·압축·압축 풀기를 창 없이 처리합니다.
  - 새로 만들 때는 현재 폴더 목록을 읽고 `uniqueName`으로 겹치지 않는 기본 이름을 고릅니다. 대소문자를 구분하지 않고, 파일은 확장자 앞에 번호를 붙입니다.
- `Explorer`
  - 만든 항목이 새 목록에 나타나면 그 행을 선택하고 이름 입력을 엽니다.
  - 다른 폴더로 가거나 그 항목이 사라지면 편집을 끝냅니다.
- 검색 결과(`App`)
  - 같은 입력칸을 씁니다. 바꾼 뒤 다시 검색하면 새 경로의 결과를 다시 선택합니다.
- 검색창·탐색창 사이 Tab 이동은 이름 입력칸 안에서는 쓰지 않습니다. 그 안의 Tab은 적용입니다.

## 검증

- **단위 테스트:** `uniqueName`(번호 매기기, 대소문자, 확장자, 점이 든 폴더 이름).
- **E2E(macOS 실제 앱):**
  - **actions:**
    - 새 폴더·새 파일·이름 변경·ZIP 압축·압축 풀기를 창 없이 처리하는지
    - 기본 이름이 맞는지
    - 예약 이름은 입력칸에 남아 안내하는지
  - **clipboard:**
    - 목록을 다시 읽는 중 F2가 동작하는지
    - 확장자 앞까지만 선택되는지
    - 이름 칸의 Ctrl+V가 파일을 붙여넣지 않는지
    - Esc로 취소하는지
    - Ctrl+Shift+N이 `새 폴더`를 바로 만드는지
  - **ux:** 이름을 바꾸거나 새 폴더를 만든 뒤 새 항목을 선택하고 초점을 두는지
  - **audit:**
    - 탭 머리글 안에서 이름을 바꾸는지
    - 두 번 눌러 시작하는지
    - Esc로 취소하는지
  - **desktop:** 메뉴의 새 텍스트 파일
  - **shell-new(Windows 전용):** Windows 새로 만들기로 만든 파일을 F2로 고치는지
- **헤드리스 Chromium 실제 키 입력:**
  - 이름 복사 → Esc → 다른 파일 F2 → Ctrl+V → 이름만 들어가고 파일 수가 변하지 않는지
  - 다른 곳 클릭 시 적용되는지
  - 목록·격자 보기 화면

**결과:**
- macOS 전체 E2E: 17개 스위트, 364개 항목 통과
- 단위 테스트 통과
- Windows 전용 스위트(shell-new 등)는 이 Mac에서 돌리지 못했습니다. 푸시 뒤 CI에서 확인합니다.
