# Windows 호환성 개선 기록

2026-10-24, `codex/project-work` 브랜치. 개선은 0.7.5 빌드에 포함된다. 기존 v0.7.4 설치 파일에는 소급 반영되지 않는다. 이후 초성 검색 성능 및 전체 E2E 결과는 [0.7.5 검증 기록](e2e-v0.7.5.md)을 참고한다.

## 수정과 추가 기능

| 항목 | 확인한 문제 | 반영한 개선 |
| --- | --- | --- |
| 경로 표시 | 드라이브 이름의 `\\?\` 접두사와 `/`를 붙여 혼합 경로 표시 | 공통 경로 함수로 검색 위치·전체 경로·행 tooltip·미리보기·빠른 검색·CSV·경로 복사를 처리. 내부 긴 경로는 보존 |
| 드라이브·UNC | 역슬래시 포함 여부만으로 구분해 `C:/`와 UNC URL을 잘못 처리 | 드라이브와 UNC를 구분하고 `file:///C:/…`, `file://server/share/…`로 생성. 공백·한글·괄호·URL 문자를 인코딩 |
| 주소 입력 | 현재 루트에만 이동 가능하고 경계와 대소문자 처리가 불명확 | 연결된 절대 경로 중 가장 가까운 루트 선택. 따옴표·구분자·`.`/`..` 처리, 범위 밖 이동 거부. Windows는 실제 인덱스 표기로 복원하고 macOS의 대소문자는 보존 |
| 이전 인덱스 | 일반 Windows 경로를 복원하면 canonical 경로와 비교가 실패할 수 있음 | 사용 가능한 저장 루트를 시작 시 canonical 경로로 복원하고 ID와 파일 목록은 유지 |
| 탭 기본 색 | 색상이 없어도 활성 탭의 파란 띠와 파란 스와치가 표시 | 첫 탭과 모든 새 탭은 무색상. 기본 띠는 투명, 선택기는 중립 팔레트 아이콘. 실제 사용자가 선택한 기존 색은 유지 |
| 탭 색상 해제 | 우클릭으로만 초기화 가능 | 별도 색상 해제 버튼과 키보드 초점 표시 추가 |
| 탐색 단축키 | 주소 편집·기록 이동·탭 닫기 단축키 부족 | Ctrl/⌘+L, Alt+D, Alt+←/→/↑, Ctrl/⌘+W 추가. 기존 Ctrl/⌘+T 유지. IME 입력 중 명령 실행 방지 |
| F5 | Windows의 일반적인 새로고침 키가 다른 창 복사를 실행 | Windows F5는 목록 새로고침, Shift+F5는 다른 창 복사. macOS F5와 F7 이동 유지. 메뉴와 도움말 갱신 |
| 숨김 파일 | 점으로 시작하는 이름만 숨김 파일로 처리 | 네이티브 인덱스에 Windows Hidden 속성을 수집해 숨김 필터와 검색 결과의 위치 표시 시 사용. 기존 인덱스는 새로고침 후 새 속성 반영 |
| 터미널 | cmd의 현재 디렉터리 전달은 UNC 작업에 적합하지 않음 | PowerShell의 `Set-Location -LiteralPath`로 전달하고 작은따옴표를 이스케이프. 한글·공백·대괄호·앰퍼샌드가 있는 폴더 검증 |
| 이름 검증 | COM/LPT의 위첨자 예약 번호와 콘솔 장치명 누락 | 프런트엔드와 Rust에서 `COM¹/²/³`, `LPT¹/²/³`, `CONIN$`, `CONOUT$`를 사전 거부 |
| 휴지통 복원 | 상대 부모 경로에서 운영체제 구분자가 다시 유입될 수 있음 | 엔진에 전달하는 상대 경로를 `/`로 통일 |
| 웹 이미지 작업 | Windows에서 libvips 파일 캐시가 변환 이미지의 즉시 이동·삭제를 막음 | Windows에서 열린 파일 캐시를 비활성화. 실제 실패했던 변환 테스트 통과 |
| Windows 검증 | 파일 심볼릭 링크 생성 권한 및 `|` 파일명 때문에 기존 테스트 실패 | 링크 경계 테스트는 일반 권한의 junction 사용. `|` 검색 구문은 가상 인덱스 항목으로 검증. 네이티브 WebView2 회귀 테스트와 CI 단계 추가 |

## 최초 Windows 수정 검증

Windows x64에서 Node 24.13.0, Rust MSVC 1.99.1과 설치된 WebView2로 실행했다.

- `npm test`: 38개 통과. 실제 파일 복사·이동·이름 변경·ZIP·휴지통·감시·이미지·OCR·HTTP 및 경로·탭 테스트.
- `npm run test:rust`: 34개 통과. 20만 항목 벤치마크 1개는 기존대로 명시적 실행 대상으로 제외.
- `npm run test:windows-ui`: 격리된 실제 WebView2에서 10개 검증 통과. 기본 탭의 투명 띠, 색상 지정·해제, 색상 상속 없음, 주소 전체 선택, 대소문자 다른 주소, 이동 기록, 탭 열기·닫기, 숨김 필터, F5 새로고침, 오류 주소를 확인. OS 클립보드를 변경하지 않는다.
- `npm run build`: TypeScript 검사와 프런트엔드 번들 생성.
- Rust Windows 회귀 테스트는 260자보다 긴 경로의 파일 삭제·복원, 기존 인덱스 재열기, Hidden 속성과 특수문자 폴더의 실제 PowerShell 위치 이동을 포함한다.

`test:windows-ui`는 검증 전용 EXE를 debug 경로에 빌드한다. 일반 앱을 실행하려면 이후 `npm run desktop:build -- --debug --no-bundle` 또는 정식 빌드 명령으로 다시 빌드한다. 테스트 자료와 JSON 결과는 출력된 임시 폴더에 남는다. 메인·빠른 검색 WebView의 검증 프로필은 모두 격리한다.

## 후속 개발 후보와 실제 환경 검증

이번에는 주소·키보드 탐색·탭 색상 해제를 추가 구현했다. 다음 항목은 별도 범위로 남긴다.

1. **네트워크 드라이브 연결 상태와 재연결**: UNC 표시·파싱은 자동 검증했지만 실제 SMB 서버의 인증 만료, 오프라인 전환, 감시 이벤트 전달은 실환경 검증이 필요하다. 연결 상태와 재시도 동작을 추가할 수 있다.
2. **Windows 탐색기에서 외부 드래그로 가져오기**: 0.7.6에서 외부 파일 드롭과 폴더 목적지 가져오기를 구현했다. 변경과 검증 경계는 [0.7.6 기록](e2e-v0.7.6.md)을 참고한다.
3. **대용량 복사·이동 진행률과 취소**: 현재 직렬 파일 작업에 바이트 단위 진행률과 안전한 취소 시점을 추가하면 큰 폴더 작업의 상태가 분명해진다.
4. **작업 실행 취소**: 일반 Undo를 추가하려면 이름 충돌, 원본 변경, 드라이브 간 이동의 복구 정책과 작업 기록이 필요하다.

실제 SMB 공유, 다중 모니터/DPI, 기본 앱 연결 및 Windows 자동 시작의 설치·재부팅 경로까지 검증했다고 보지는 않는다. macOS 실기기는 이번 환경에서 재검증하지 않았다.

파일명 규칙은 [Microsoft 파일·경로 규칙](https://learn.microsoft.com/windows/win32/fileio/naming-a-file), 터미널 전달 방식은 [Set-Location의 LiteralPath](https://learn.microsoft.com/powershell/module/microsoft.powershell.management/set-location?view=powershell-5.1)를 참고했다.
